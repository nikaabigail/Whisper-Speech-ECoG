# Результаты

[← На главную](../README.md) · [Архитектура](../docs/ARCHITECTURE.md) ·
[Происхождение чисел](../docs/PROVENANCE.md)

Папка содержит только агрегированные, пригодные для публикации метрики и
графики. Сырые прогнозы, нейрофизиологические данные, временные ряды и кэши сюда
не входят.

`reported_metrics.json` является машинно читаемым источником для сводных таблиц
и **двух summary PNG**: `sync/sync_l345_seed4.png` и
`async/figures/async_f1_ci.png`. Их регенерирует `plot_reported_metrics.py`.

`async/figures/paper_style_async_pr_multiseed.png` — зафиксированный reported-
артефакт, а не третий график из `reported_metrics.json`. В релиз включён CSV с
плотными test PR-точками пяти head seeds, но для побитовой регенерации PR-фигуры
также нужны приватные final-result и null/chance arrays, которые не публикуются.

Здесь `accuracy` — доля правильно выбранных слов на заранее выровненных
примерах. Она не эквивалентна event-F1 непрерывного эксперимента.

## Непрерывная задача: validation-selected operating point

Порог каждой модели/ансамбля выбран по validation и затем без изменения применён
к test. `n=5` относится к continuous-head seeds; upstream seed во всех пяти
запусках равен 4.

Это **офлайн- и некаузальная** асинхронная оценка. Pipeline использует
zero-phase `decimate`, `filtfilt`, нормировку по целой записи и центрированное
сглаживание 200 мс (около 100 мс будущего контекста), поэтому эти числа нельзя
интерпретировать как результат strict real-time deployment. Голова выдаёт 27
классов (`silence + 26 слов`); событие считается TP только при правильном классе
слова и попадании времени детекции в заданный допуск.

| Система | F1 mean | SD | 95% t-CI |
|---|---:|---:|---:|
| L3 | 0,4540 | 0,0097 | [0,4420; 0,4660] |
| L4 | 0,4602 | 0,0130 | [0,4440; 0,4763] |
| L5 | 0,4312 | 0,0127 | [0,4154; 0,4470] |
| **L3+L4+L5** | **0,5059** | **0,0102** | **[0,4932; 0,5186]** |

Для ансамбля:

- Precision: `0,5050`;
- Recall: `0,5088`;
- event PR-AUC: `0,4270 ± 0,0127 SD`, 95% t-CI `[0,4112; 0,4428]`;
- ложные срабатывания: `19,65 в минуту`;
- медианная задержка обнаружения: около `167 ms`.

![F1 с 95% доверительными интервалами](async/figures/async_f1_ci.png)

В этом отчёте event PR-AUC — трапецеидальная площадь под верхней огибающей
precision на фактически достигнутом диапазоне recall. Это не
`sklearn.average_precision` и не площадь, дополненная до всего `[0; 1]`.

## Непрерывная задача: описательный срез Recall ≈ 0,40

| Система | Precision mean ± SD | Recall mean ± SD | F1 mean ± SD |
|---|---:|---:|---:|
| L3 | 0,5061 ± 0,0122 | 0,4009 ± 0,0021 | 0,4474 ± 0,0049 |
| L4 | 0,5436 ± 0,0196 | 0,4014 ± 0,0021 | 0,4617 ± 0,0076 |
| L5 | 0,4613 ± 0,0344 | 0,4023 ± 0,0016 | 0,4293 ± 0,0147 |
| **L3+L4+L5** | **0,6380 ± 0,0097** | **0,3991 ± 0,0027** | **0,4910 ± 0,0044** |

Для ансамбля: F1 95% t-CI `[0,4856; 0,4964]`, `8,83 ± 0,34 FP/min`,
медианная задержка `167,9 ± 5,6 ms`.

![Precision–Recall](async/figures/paper_style_async_pr_multiseed.png)

[CSV с плотными test PR-кривыми пяти head seeds](async/paper_style_async_pr_multiseed.csv)
содержит только агрегированные точки `threshold/precision/recall/F1/FP-per-min`
и не включает исходные сигналы, timelines или локальные пути.

Это post-hoc точка тестовой кривой: ближайший к 0,40 recall выбирается с помощью
test labels. Её нельзя использовать как доказательство качества заранее
зафиксированного порога. Для основного вывода используйте предыдущий раздел.

## Как читать интервалы

- `SD` показывает разброс пяти head seeds.
- `SEM = SD / √n` характеризует неопределённость среднего при данных запусках.
- 95% t-CI рассчитан по t-распределению при `df=4`.
- Интервалы **не включают** вариативность upstream-обучения, пациентов, splits и
  разметки, потому что они во всех пяти запусках зафиксированы.

Следовательно, эти интервалы нельзя интерпретировать как популяционную
неопределённость метода или межпациентную обобщаемость.

## Правила обновления

1. Не редактировать PNG вручную.
2. Сначала обновить машинно читаемую таблицу и provenance.
3. Перегенерировать **два summary PNG** через `plot_reported_metrics.py`.
4. PR-фигуру регенерировать отдельным async-report pipeline только при наличии
   исходных private final-result и null/chance arrays; иначе сохранять её как
   неизменный curated reported artifact и сверять с опубликованным CSV.
5. Проверить подписи осей, n, определение error bars и operating point.
6. Сверить README с JSON/CSV и только затем коммитить.
