# 04 · Whisper: асинхронное / непрерывное декодирование

[← Ансамбль](../03_whisper_ensemble/README.md) · [На главную](../README.md) ·
[Результаты →](../results/README.md)

Здесь декодер получает непрерывную запись и не получает temporal cue о начале
слова. Он скользит по времени, и для конечной точки каждого окна выдаёт softmax
по **27 классам**: `silence + 26 слов`. Кандидаты событий строятся из локальных
максимумов временных профилей вероятности нетишинных классов. Кандидат считается
true positive только тогда, когда предсказан правильный класс слова и время
детекции попало в заданный интервал/допуск истинного события. Поэтому это не
бинарная `word present / absent`-голова, а 27-классовая endpoint-классификация с
последующим event matching.

## Важно: это offline/noncausal async, а не strict real-time

В этой работе «асинхронный» означает отсутствие известной границы слова и
оценку на непрерывной временной сетке. Текущая реализация при этом использует
будущий контекст:

- `scipy.signal.decimate` вызывается с zero-phase-фильтрацией;
- несколько фильтров применяются через `filtfilt`;
- `sklearn`-нормировка использует статистики целой записи;
- центрированное сглаживание вероятностей шириной 200 мс видит примерно 100 мс
  будущих значений.

Следовательно, зафиксированные F1, FP/min и latency относятся к **офлайн,
некаузальной, boundary-free** оценке. Их нельзя выдавать за характеристики
строгого потокового real-time deployment; для него нужны каузальные фильтры,
онлайн-нормировка и односторонний постпроцессинг с новым измерением качества и
задержки.

## Два разных эксперимента

### A. Frozen replay

`async_replay.py` применяет уже обученные синхронные L3/L4/L5-модели к плотной
временной сетке без дообучения. Этот эксперимент отвечает на узкий вопрос:
«переносится ли синхронное решение на непрерывный поток как есть?»

Зафиксированный ансамбль в такой реконструкции дал примерно
`Precision=0,125`, `Recall=0,123`, `F1=0,124`, `33,72 FP/min` и медианную
задержку около `429 ms`. Низкий результат ожидаем: синхронная модель не училась
отделять произвольный фон от события во всех положениях скользящего окна.

### B. Continuous-head training

В основном эксперименте upstream-регрессионные энкодеры L3/L4/L5 заморожены.
Они преобразуют непрерывные окна в 3030D-признаки. Для каждого слоя создаётся
тот же 27-классовый `Mel2WordHidden`, **целиком warm-started** из синхронного
seed-4 checkpoint, и все параметры этой головы дообучаются на trailing-окнах из
52 hidden-кадров. После этого вероятности трёх голов усредняются.

Upstream сохраняет историческое окно `LAG_BACKWARD=1000` downsampled samples с
обеими включёнными границами (1001 отсчёт). Это номинально около 1 с, но для
`ivanova` при 1024 Гц между концами окна 976,6 мс, а не ровно 1000 мс.
Последовательные hidden-признаки идут с шагом 10 отсчётов, то есть 102,4 Гц;
52 кадра охватывают 51 интервал, или `51 × 10 / 1024 ≈ 0,498 с`. Поэтому
номинальный trailing receptive span одного continuous-выхода в исходном ECoG
равен примерно `0,977 + 0,498 = 1,475 с`. Это геометрия окон до учёта описанного
выше некаузального препроцессинга, который дополнительно использует будущее.

| Файл | Назначение |
|---|---|
| `build_continuous_cache.py` | построение кэша скрытых признаков замороженных энкодеров |
| `train_continuous_heads.py` | обучение, validation-selection и закрытая test-оценка |
| `summarize_continuous_multiseed.py` | агрегирование нескольких head seeds |
| `continuous_common.py` | общие структуры, проверки архива и метрики |
| `paper_pr_curve/build_paper_style_pr.py` | единая PR-кривая и точки сидов |
| `paper_pr_curve/summarize_recall40.py` | описательный срез при Recall около 0,40 |
| `run_frozen_replay.ps1` | portable PowerShell-запуск frozen replay |
| `run_continuous_multiseed.ps1` | полный train/validation/test-gated multiseed |

Кэш может занимать десятки гигабайт и хранится вне git.

## Запуск

Проверить frozen replay без загрузки моделей:

```powershell
.\run_frozen_replay.ps1 -PreflightOnly
```

Запустить сам replay L3+L4+L5:

```powershell
.\run_frozen_replay.ps1 -Layers 3,4,5 -Seed 4 -NoSaveTimelines
```

Проверить пути, frozen archive и continuous cache до ночного запуска:

```powershell
.\run_continuous_multiseed.ps1 -PreflightOnly
```

Полный fresh multiseed с test gate:

```powershell
.\run_continuous_multiseed.ps1 -Seeds 1,2,3,4,42 -Epochs 30 -MinEpochs 5 -Patience 5
```

Повтор той же команды безопасно переиспользует завершённые стадии. Локальные
входы и ожидаемый layout архива описаны в
[checkpoints/README.md](../checkpoints/README.md).

## Основной multiseed-результат

Пять инициализаций continuous-head (`1, 2, 3, 4, 42`) используют один и тот же
замороженный upstream `seed=4`. Следовательно, дисперсия ниже отражает
стабильность **головы**, но не полную неопределённость всего пайплайна.

| Система | F1, mean ± SD | 95% t-CI |
|---|---:|---:|
| L3 | 0,4540 ± 0,0097 | [0,4420; 0,4660] |
| L4 | 0,4602 ± 0,0130 | [0,4440; 0,4763] |
| L5 | 0,4312 ± 0,0127 | [0,4154; 0,4470] |
| **L3+L4+L5** | **0,5059 ± 0,0102** | **[0,4932; 0,5186]** |

Для ансамбля: `Precision=0,5050`, `Recall=0,5088`,
`event PR-AUC=0,4270 ± 0,0127 SD` с 95% t-CI `[0,4112; 0,4428]`,
`19,65 FP/min`, медианная задержка около `167 ms`.

Здесь event PR-AUC вычисляется трапецеидальным интегрированием **верхней
огибающей precision** только по фактически достигнутому диапазону recall. Это
не `sklearn.average_precision` и не площадь, искусственно дополненная до всего
диапазона recall `[0; 1]`.

## Срез Recall ≈ 0,40

| Система | Precision, mean ± SD | Recall, mean ± SD | F1, mean ± SD |
|---|---:|---:|---:|
| L3 | 0,5061 ± 0,0122 | 0,4009 ± 0,0021 | 0,4474 ± 0,0049 |
| L4 | 0,5436 ± 0,0196 | 0,4014 ± 0,0021 | 0,4617 ± 0,0076 |
| L5 | 0,4613 ± 0,0344 | 0,4023 ± 0,0016 | 0,4293 ± 0,0147 |
| **L3+L4+L5** | **0,6380 ± 0,0097** | **0,3991 ± 0,0027** | **0,4910 ± 0,0044** |

Для ансамбля 95% t-CI F1 `[0,4856; 0,4964]`, `8,83 ± 0,34 FP/min`,
задержка `167,9 ± 5,6 ms`.

![PR-кривая](../results/async/figures/paper_style_async_pr_multiseed.png)

**Важно:** точка выбрана как ближайшая к `Recall=0,40` на тестовой PR-кривой,
то есть с использованием тестовых меток. Она подходит для описания формы кривой
и визуального сопоставления со статьёй, но не является независимой рабочей точкой
для deployment. Основной отчёт использует порог, выбранный только на validation.

## Связь со статьёй

В статье описан асинхронный эксперимент, но его исполняемый код не найден в
публичном репозитории и доступной истории. Поэтому:

- frozen replay — наша документированная реконструкция идеи;
- continuous-head — наше расширение с Whisper;
- близость графика или значения при Recall≈0,40 не доказывает тождество
  архитектур, постпроцессинга или протокола оценки.

Для строгого утверждения «MEL заменён на Whisper при неизменном всём остальном»
потребовались бы официальный async-код, точные splits, параметры скольжения,
правило matching событий и код подсчёта метрик.
