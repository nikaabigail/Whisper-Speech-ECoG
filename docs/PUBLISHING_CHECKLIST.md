# Чек-лист перед публикацией

[← На главную](../README.md) · [Происхождение](PROVENANCE.md) ·
[Веса](../checkpoints/README.md)

Пока обязательные пункты ниже не закрыты, каталог следует считать внутренним
release candidate, а не готовым публичным репозиторием.

## 1. Право и этика — обязательные блокеры

- [ ] Выбрана и одобрена лицензия **для нашего кода**; файл `LICENSE` добавлен
  только после такого решения.
- [ ] Проверены условия использования upstream MEL-кода; отсутствие LICENSE не
  интерпретируется как разрешение на копирование.
- [ ] Проверены лицензии Whisper, PyTorch и остальных распространяемых
  зависимостей/ассетов.
- [ ] Ответственный исследователь подтвердил, какие производные артефакты можно
  публиковать.
- [ ] Условия информированного согласия и data-use agreement допускают выбранный
  способ публикации.
- [ ] Отдельно принято решение по весам, хэшам весов и model inversion/privacy
  рискам.
- [ ] Текст статьи и PDF не копируются в репозиторий без права распространения;
  используется библиографическая ссылка.

## 2. Данные и приватность

- [ ] Нет `patients.json`, реальных имён, идентификаторов, дат процедур и
  соответствий псевдонимов.
- [ ] Нет абсолютных пользовательских путей, имён Windows-профилей и сетевых
  адресов.
- [ ] Нет `.h5`, `.hdf5`, `.npy`, `.npz`, сырых timeline/feature/cache файлов.
- [ ] Нет физических `__pycache__/` и `.pyc` (одного правила `.gitignore`
  недостаточно для чистого release archive).
- [ ] Нет логов и traceback, которые раскрывают локальные пути или метаданные.
- [ ] PNG/SVG проверены на отсутствие чувствительных подписей и embedded metadata.

## 3. Веса и большие файлы

- [ ] `.pth`, `.pt`, `.ckpt` отсутствуют либо каждый файл имеет отдельное
  разрешение на публикацию.
- [ ] Для разрешённых весов опубликованы назначение, upstream/head seed, размер и
  SHA-256.
- [ ] Git LFS настроен, если разрешённые файлы требуют его.
- [ ] Hidden cache и производные признаки не используются как способ обойти
  запрет на публикацию исходных данных.

## 4. Научная корректность

- [ ] `accuracy` синхронной задачи не сравнивается напрямую с async event-F1.
- [ ] Везде указано `n=445` для фиксированного sync seed4 результата.
- [ ] `LAG_1000_0` описан как 1000 downsampled samples/1001-sample inclusive
  window, а не как ровно 1000 мс.
- [ ] Continuous multiseed помечен как условный на upstream seed4.
- [ ] Error bars однозначно названы: SD или 95% t-CI, без смешения.
- [ ] Основной async threshold выбран на validation.
- [ ] Recall≈0,40 помечен как описательный test-curve slice.
- [ ] Async-результат явно назван offline/noncausal, а не strict real-time.
- [ ] Continuous-head описан как 27-классовая endpoint-задача; event TP требует
  правильного класса слова и попадания в временной допуск.
- [ ] Event PR-AUC определён как trapezoid по upper precision envelope на
  достигнутом recall-range и не назван `average_precision`.
- [ ] Не заявлено точное воспроизведение официального async-кода статьи.
- [ ] Перечислены различия matching, window/stride, postprocessing и splits, если
  сравнение со статьёй всё же проводится.
- [ ] Машинно читаемые метрики совпадают с README и PNG.

## 5. Техническая проверка

- [ ] Все Python-файлы проходят AST/compile smoke test.
- [ ] Все entry points отвечают на `--help` без доступа к данным.
- [ ] PowerShell-скрипты парсятся в Windows PowerShell 5.1 и PowerShell 7.
- [ ] HDF5 открывается только на чтение там, где запись не требуется.
- [ ] Конфигурация данных загружается извне; публичный example не содержит
  реальных путей.
- [ ] Запуск с отсутствующими весами завершается понятной ошибкой до долгой работы.
- [ ] Test gate запрещает открывать test cache до фиксации голов.
- [ ] Повторная оценка существующих голов не удаляет чекпойнты.
- [ ] Два summary PNG воспроизводятся из `reported_metrics.json` через
  `plot_reported_metrics.py`.
- [ ] PR PNG помечен как curated reported artifact; документировано, что его
  точная регенерация требует private final-result и null/chance arrays.

Если в релизе присутствует `scripts/check_release.ps1`, выполните:

```powershell
.\scripts\check_release.ps1
```

Дополнительные ручные проверки:

```powershell
git diff --check
git status --short
rg -n "[A-Z]:\\|Users\\|AppData|D:\\" .
rg -n "password|passwd|token|api[_-]?key|secret" . -i
Get-ChildItem -Recurse -File | Sort-Object Length -Descending |
    Select-Object -First 20 FullName, Length
```

Совпадение по словам `token` или `secret` может быть безопасным упоминанием в
документации; каждое совпадение нужно просмотреть вручную.

## 6. Документация и навигация

- [ ] Все относительные ссылки README открываются на GitHub.
- [ ] Три PNG отображаются на главной странице.
- [ ] На каждом графике видны оси, единицы, n и смысл интервала.
- [ ] `PROVENANCE.md` содержит актуальные commit и дату сборки.
- [ ] Команды запуска соответствуют фактическим именам файлов.
- [ ] Ограничения воспроизводимости заметны до раздела запуска, а не спрятаны в
  конце.

## 7. Финальный git-аудит

- [ ] Репозиторий создаётся из чистой папки, а не из рабочего дерева с историей
  данных.
- [ ] `.gitignore` проверен тестовыми файлами запрещённых типов.
- [ ] Первый commit просмотрен через `git status` и `git diff --cached --stat`.
- [ ] В remote нет старых веток/тегов с данными или весами.
- [ ] Публичность включается только после вторичного просмотра другим участником.

Рекомендуемый принцип: если статус артефакта неясен, не публиковать его до
формального решения; документацию и код можно подготовить отдельно.
