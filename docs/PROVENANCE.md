### Локальная линия Whisper

Чистые файлы выделены из рабочих проектов в отдельное дерево. Исходные рабочие
каталоги и хранилище данных при этой операции не изменялись. В релиз перенесён
только минимальный closure актуальных Python-модулей:

- `02_whisper_sync/` — синхронное обучение L3/L4/L5;
- `03_whisper_ensemble/` — фиксированное усреднение softmax;
- `04_whisper_async/` — frozen replay, continuous cache/head и отчётность.

Из чистой копии удалены или не переносились старые запуски, временные hotfix-
скрипты, логи, кэши, сырые данные и лишние чекпойнты. Портируемые пути указывают
на соседние каталоги релиза или задаются параметрами/переменными окружения.

## Происхождение чисел

### Синхронный seed 4

Результаты L3/L4/L5 и L3+L4+L5 перенесены из завершённого фиксированного отчёта
для `ivanova`, `seed=4`, `n=445`. Все четыре значения относятся к одной тестовой
поверхности. В чистом репозитории они являются **reported results**, а не новым
вычислением без данных и весов.

### Continuous multiseed

Пять head seeds (`1, 2, 3, 4, 42`) завершили fixed-test evaluation после выбора
checkpoint и threshold на validation. Сводка условна на:

- одном пациенте;
- одном split;
- одном комплекте upstream Whisper-энкодеров `seed=4`;
- фиксированном ансамбле L3+L4+L5.

Средние, SD, SEM и 95% t-CI восстановлены из сохранённых per-seed результатов.

### PR-срез Recall≈0,40

Для каждого head seed выбрана ближайшая точка полной **test** PR-кривой. Числа
полезны для визуального сопоставления с областью, показанной в статье, но являются
описательными. Они не подтверждают качество порога, выбранного без test labels.

Опубликованный PR PNG является зафиксированным reported-артефактом. В релизе
есть плотные per-seed test PR-точки в CSV, но точная регенерация оформления и
null/chance-компонентов также требует приватные final-result и null/chance
arrays, которые не включены. `reported_metrics.json` воспроизводит только два
summary PNG: синхронное сравнение и F1 с доверительными интервалами.

## Статус асинхронного кода

| Компонент | Статус |
|---|---|
| Синхронный MEL upstream | публичный внешний код |
| Синхронный Whisper | локальная реализованная замена target-представления |
| Whisper L3+L4+L5 | локальная реализованная агрегация |
| Frozen async replay | реконструкция постановки по описанию |
| Continuous-head | локальное offline/noncausal расширение с 27-way endpoint-обучением |
| Async-код авторов статьи | не найден в публичном upstream |

Поэтому в статье/README нельзя писать «точно воспроизведён официальный
асинхронный декодер». Допустимо: «реализована реконструкция по опубликованному
описанию; затем MEL-подобная линия заменена на Whisper representation» — при
условии явного перечисления всех несовпадающих деталей.

## Данные и веса

Ни один из следующих артефактов не является частью публичного кандидата:

- нейрофизиологические записи;
- разметка с чувствительными метаданными;
- локальная конфигурация пациентов;
- dense timelines и hidden caches;
- обученные веса.

Контрольные суммы в release manifest, если он публикуется, подтверждают
целостность разрешённой внутренней копии, но не дают права распространять сам
payload.

## Что нужно записать при новом результате

Для каждого нового запуска необходимо сохранить:

- commit чистого репозитория и версию внешнего upstream;
- версии Python, PyTorch/CUDA и ключевых библиотек;
- patient pseudonym, split fingerprint и upstream/head seeds;
- параметры окна, lag, шага, matching и postprocessing;
- правило выбора checkpoint и threshold;
- SHA-256 всех использованных весов;
- per-seed метрики и агрегирование, включая точное определение CI.

Без этой информации число не следует добавлять в главную таблицу.
